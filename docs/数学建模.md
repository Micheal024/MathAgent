# 数学建模答疑Agent：产品需求文档 (PRD)

本项目旨在设计并开发一款能够解析数学建模题目并提供初步建议的智能答疑Agent。该Agent的核心定位并非一个简单的问答机器人，而是一个基于自主代理式检索增强生成（Agentic RAG）架构的、能够主动规划与执行复杂任务的研究助理 [[28](https://medium.com/@adnanmasood/beyond-retrieval-agentic-vs-traditional-retrieval-augmented-generation-9ee50c8242c2)]。传统RAG系统被动地接收查询并返回信息，如同图书馆员递送书籍；而Agentic RAG则更像一位能够阅读文献、交叉验证证据、使用工具（如计算器）并起草报告的研究生助理 [[28](https://medium.com/@adnanmasood/beyond-retrieval-agentic-vs-traditional-retrieval-augmented-generation-9ee50c8242c2)]。这一根本差异决定了项目的技术复杂度和功能深度。其架构将围绕两大核心支柱展开：一是具备高级推理与规划能力的“智能体”（Agent），二是能够处理高度专业化、结构化知识的“检索增强生成”（RAG）引擎。

项目的整体架构分为前端和后端两部分，通过一个清晰、流程化的交互模式连接。用户首先输入待解决的数学建模题目。系统后端接收到请求后，启动第一个核心阶段——“初步解析”。此阶段的目标是深入理解问题，并为用户提供有价值的前期指导。具体流程包括：首先，对题目文本进行自然语言理解，提取关键实体，如研究领域、核心目标、约束条件、可用数据集等，这构成了问题澄清与假设简化的初始步骤 [[49](https://blog.csdn.net/weixin_26805451/article/details/150076073)]。随后，系统利用强大的RAG引擎，在海量的科学文献数据库中进行语义层面的深度检索，而非简单的关键词匹配 [[21](https://www.sciencedirect.com/science/article/pii/S294971912500055X), [25](https://arxiv.org/html/2410.05779v3)]。检索结果不仅包含相关论文，更重要的是，系统会结合大语言模型（LLM）的能力，对这些文献进行自动归纳，提炼出当前领域的研究热点、常用模型方法、关键概念以及潜在的研究空白，从而为用户勾勒出一条清晰的研究方向 [[56](https://medium.com/@fahey_james/large-reasoning-models-lrms-an-overview-19837b72540f)]。最终，系统将整合后的题目理解、文献摘要和研究建议呈现给用户。这个过程类似于Synergistic multi-stage RAG架构，它通过结构化文档解析、领域特定嵌入微调和新颖的“摘要优先”检索策略，显著提升了上下文的相关性 [[21](https://www.sciencedirect.com/science/article/pii/S294971912500055X)]。

在用户确认了初步解析结果后，流程进入第二阶段——“解题思路生成”。此时，Agent不再是单纯的文献检索者，而是开始扮演一个“思维链”的引导者。它会根据已确定的研究方向和问题本质，将宏观的建模任务分解为一系列微观的、可操作的步骤。例如，对于一个优化问题，Agent可能会建议：“第一步，建立决策变量和目标函数；第二步，定义约束条件，考虑非线性或整数约束；第三步，选择合适的求解算法，如遗传算法或内点法；第四步，进行敏感性分析。” 这种分步式的指导极大地降低了学生的认知负荷，帮助他们构建起完整的解题框架。此阶段的输出将是一份结构化的解题思路文档，同样需要用户确认，以确保后续的自动化辅助写作符合其预期。

当用户确认了解题思路后，系统便进入第三个核心阶段——“论文书写与协同编辑”。这是一个类似Canvas的在线富文本编辑器，用户可以在此环境中完成论文的主体撰写。编辑器的核心优势在于其与解题思路模块的联动能力。例如，用户点击解题思路中的某个章节（如“模型假设”），对应的编辑区域即可自动填充相关内容的占位符和提示，甚至可以直接插入相关的公式或图表模板。此外，为了满足团队合作的需求，编辑器必须具备实时协同编辑功能，允许多名成员同时对同一份稿件进行修改、评论和讨论 [[1](https://liveblocks.io/blog/which-rich-text-editor-framework-should-you-choose-in-2025), [3](https://block-suite.com/blog/document-centric.html)]。最后，在论文撰写完成后，系统将启动第四个阶段——“多格式输出与导出”。用户可以根据不同竞赛的要求，一键生成Word (.docx)、PDF和LaTeX三种格式的文件 [[19](https://www.braintrust.dev/articles/top-10-llm-observability-tools-2025)]。这一系列功能的无缝集成，共同构成了一套覆盖“问题理解-文献调研-方案构思-论文撰写-成果交付”全链条的智能化数学建模支持平台。其成功的关键在于能否有效融合先进的AI技术与专业的学术工作流，真正成为学生团队的得力助手。

### 2.3 数学建模题目特征与解题流程

#### 2.3.1 题目类型分析

根据历年赛题统计，数学建模题目主要分为以下类型：

**优化类问题**：出现频率最高，几乎每年都会出 1-2 道题目。这类问题要求在给定约束条件下寻找最优解，常用算法包括线性规划、非线性规划、动态规划、遗传算法、模拟退火等[(131)](https://blog.csdn.net/Magnolia_He/article/details/141742603)。

**评价类问题**：要求建立评价指标体系，对某一对象进行综合评价。

**预测类问题**：基于历史数据预测未来趋势，主要使用统计学方法和机器学习算法。

**机理分析类问题**：需要深入理解问题的物理或化学机理，建立相应的数学模型。

#### 2.3.2 标准解题流程

数学建模的标准流程包括以下步骤：

1. **问题理解与重述**：准确理解题目要求，明确目标和约束条件
2. **模型假设**：提出合理的假设，简化问题复杂度
3. **模型建立**：选择合适的数学方法建立模型
4. **模型求解**：使用数学方法或计算机算法求解模型
5. **结果分析与验证**：分析结果的合理性，进行敏感性分析
6. **模型改进**：根据分析结果改进模型
7. **论文撰写**：按照竞赛要求撰写完整的学术论文



### 功能模块详解

#### 阶段一：智能解析与文献调研（The Analyst）

此阶段的目标是“破题”。用户输入题目文本或上传PDF后，系统进入解析模式。

1. **题目结构化拆解：**
   1. **输入：** 原始赛题文本。
   2. **处理逻辑：** Agent利用NLP技术提取关键实体：**目标函数（Objective）**、**约束条件（Constraints）**、**决策变量（Decision Variables）**、**已知参数（Parameters）**。
   3. **输出展示：** 在UI左侧展示结构化卡片，而非纯文本。例如，将“车辆不得超载”自动转化为约束条件 $TotalWeight \le MaxCapacity$ 的初步数学表达。
2. **增强型文献搜索（RAG-based Literature Review）：**
   1. **痛点：** 学生往往不知道该搜什么关键词。
   2. **解决方案：** Agent根据提取的实体自动生成3-5组检索词，调用**Semantic Scholar API**或**Crossref API**进行实时检索 (8)。
   3. **筛选机制：** 优先展示高引用（Citation Count > 50）且发表年份较新（近5-10年）的文献，重点抓取包含“Model”、“Algorithm”关键词的论文。
   4. **输出：** “推荐阅读文献列表”，并附带Agent生成的简短摘要，说明该文献对本题的参考价值（例如：“文献提出的改进遗传算法可用于解决本题的第二问”）。
3. **初步建议生成：**
   1. 综合题目意图和检索到的文献，Agent生成一份《初步解析报告》，包含问题重述、核心难点分析及推荐的模型类别。
   2. **用户确认节点（Gate 1）：** 界面底部出现“确认解析”按钮。用户可修改Agent提取的约束条件或关键词。只有用户点击确认后，系统才会解锁下一阶段。

#### 阶段二：解题思路与策略规划（The Strategist）

此阶段的目标是构建“解题路线图”。

1. **多模态策略推荐：**
   1. Agent应用**思维树（Tree of Thoughts）**技术，生成A、B、C三套不同技术路线的方案 (10)。
      - *方案A（经典路线）：* 使用成熟、稳健的模型（如线性回归、Dijkstra）。风险低，创新分一般。
      - *方案B（进阶路线）：* 使用较复杂的现代算法（如深度学习、模拟退火）。难度高，创新分高。
      - *方案C（创新路线）：* 结合跨学科方法的独特视角。
   2. **表格化对比：** 系统自动生成一张对比表，列出每种方案的“数学难度”、“编程复杂度”、“数据需求量”及“预期效果”，辅助用户决策。
2. **代码框架预生成：**
   1. 用户选定路线后（如方案B），Agent生成对应的伪代码或Python/MATLAB代码框架。注意，此时不生成完整代码，而是生成**代码骨架**（包含输入输出定义、核心库引用建议），以符合“辅助而非替代”的伦理准则。
3. **用户确认节点（Gate 2）：** 用户选定一种策略，并可对步骤进行微调（拖拽调整步骤顺序）。确认后，该路线图将作为“大纲”导入写作画布。

#### 阶段三：Canvas在线协作编辑器（The Editor）

这是产品的核心交互界面，采用“所见即所得（WYSIWYG）”的块级编辑器设计。

1. **UI布局：**
   1. **左侧：** 导航栏（大纲视图），实时显示论文结构。
   2. **中间：** Canvas画布，支持富文本编辑。
   3. **右侧：** 智能助手侧边栏（AI Copilot）。用户可随时在此与Agent对话，要求其“润色这一段”、“检查公式推导”或“生成图表代码”。
2. **块级编辑（Block-based Editing）：**
   1. 参考Notion或Overleaf Visual Mode的设计，文档由不同的“块（Block）”组成：文本块、公式块（LaTeX）、代码块、图片块、引用块。
   2. **LaTeX公式深度集成：** 用户输入 $$ 即可唤起公式编辑器，支持实时预览。底层使用KaTeX渲染，确保在Web端的高性能显示 (11)。
   3. **拖拽重组：** 支持整段文字或整个章节的拖拽移动，极大方便论文结构的调整 (13)。
3. **智能写作辅助：**
   1. **自动补全（Autocomplete）：** 基于上下文，Agent可预测下一句的内容（类似GitHub Copilot）。
   2. **关联引用（Smart Citation）：** 用户输入 @ 可直接唤起阶段一搜索到的文献，一键插入引用，并自动在文末生成参考文献列表（BibTeX格式）。

#### 阶段四：多格式导出引擎（The Publisher）

这是“最后一公里”的交付，也是技术难度最高的环节。

1. **格式适配：**
   1. **PDF：** 必须完美符合CUMCM或MCM的排版要求。系统内置多套模板（如 mcmthesis.sty），后台调用LaTeX编译器生成 (15)。
   2. **Word (.docx)：** 针对不熟悉LaTeX的用户。需保证公式在Word中可编辑（转换为OMML格式），图片和表格不乱序 (17)。
   3. **LaTeX源码 (.tex)：** 针对高阶用户，导出干净、注释清晰的源码包，方便其在Overleaf上进行二次加工。
2. **合规性检查：**
   1. **AI报告自动生成：** 导出前，系统自动抓取所有对话记录，生成《AI使用说明》附录。
   2. **页数检查：** 针对MCM/ICM 2025的25页限制，系统在导出前进行预计算，若超页则发出红色警报 (19)。
   3. **匿名检查：** 扫描文中是否包含“University”、“College”或具体的学校名称，防止违规。



1. ## 技术架构设计方案

### 3.1 整体技术架构

本系统采用前后端分离的微服务架构，主要包括以下核心组件：

**前端层**：负责用户界面展示和交互，采用现代 Web 技术栈，支持响应式设计。

**后端层**：提供核心业务逻辑和 AI 能力，采用 Spring Boot 或 Node.js 构建 RESTful API 服务。

**AI 服务层**：集成各类 AI 模型，包括数学推理模型、NLP 模型、文献检索模型等。

**数据层**：包括用户数据、题目库、文献库、模型参数等各类数据的存储和管理。

**第三方服务**：集成学术搜索引擎 API、云存储服务、支付服务等。

- 支持多标签分类（题目可能属于多种类型）

### 5.2 解题思路生成模型

#### 5.2.1 基于知识图谱的解题策略

构建数学建模知识图谱，为解题思路生成提供知识支撑：

**知识图谱构建**：

1. **实体定义**：

- 问题类型：优化、预测、评价等
- 数学方法：线性规划、神经网络、回归分析等
- 应用领域：工程、经济、社会等
- 评价指标：准确率、复杂度、适用性等

1. **关系定义**：

- "问题类型 - 适用方法"：优化问题适用线性规划
- "方法 - 应用场景"：神经网络适用于非线性预测
- "方法 - 评价指标"：线性规划的计算复杂度低

1. **推理规则**：

- IF 问题类型 = 优化 AND 目标函数 = 线性 AND 约束 = 线性 THEN 推荐方法 = 线性规划
- IF 数据量 > 1000 AND 非线性关系 THEN 推荐方法 = 神经网络

#### 5.2.2 历史案例推理机制

基于历史成功案例进行推理，生成解题建议：

**案例库设计**：

- 存储结构：题目特征 + 解题方案 + 结果评价
- 索引方式：基于问题类型、关键词、难度等
- 更新机制：用户反馈和新案例的持续添加

**相似性匹配算法**：

1. **文本相似度**：使用余弦相似度计算题目文本的相似性
2. **结构相似度**：比较问题的数学结构（如目标函数形式）
3. **特征相似度**：基于提取的关键特征进行匹配

**案例推理流程**：

1. 输入新题目，提取特征
2. 在案例库中搜索相似案例
3. 按相似度排序，返回最相似的案例
4. 基于相似案例的解题方案，生成新题目的建议

### 5.3 数学推理与验证能力

#### 5.3.1 复杂数学公式解析

数学推理是 AI 能力的核心，需要准确解析和验证数学内容：

**技术挑战**：

1. **公式结构理解**：正确识别公式中的变量、运算符、函数等
2. **语义理解**：理解数学表达式的含义和作用
3. **推理验证**：验证推导过程的正确性

**解决方案**：

1. **MathML 解析**：

- 将数学公式转换为 MathML 格式

1. **符号计算引擎**：

- 集成 SymPy 符号计算库
- 支持代数运算、微积分、方程求解

3. **敏感性分析**：分析参数变化对结果的影响
4. **对比验证**：与已知结果或近似解进行比较

**结果分析功能**：

1. **可视化分析**：将结果转换为图表形式

### 5.4 文献推荐与检索优化

#### 5.4.1 智能文献匹配算法

根据题目内容推荐最相关的学术文献：

**匹配算法**：

1. **关键词扩展**：

- 生成扩展的关键词集合

- 考虑关键词权重和位置信息

1. **多维度排序**：

- 相关性排序：基于语义相似度
- 权威性排序：基于期刊影响因子、引用次数
- 时效性排序：优先推荐近期发表的文献

#### 5.4.2 个性化推荐系统

基于用户行为提供个性化的文献推荐：

**推荐策略**：

1. **协同过滤**：

- 基于用户历史行为的协同过滤
- 发现相似用户的兴趣模式
- 推荐相似用户关注的文献

1. **内容推荐**：

- 分析用户浏览过的文献特征
- 基于内容相似度推荐相关文献
- 考虑用户的专业背景和兴趣偏好

1. **混合推荐**：

- 结合协同过滤和内容推荐的优势
- 根据不同场景选择合适的推荐算法
- 实时调整推荐策略
